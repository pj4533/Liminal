## Open task 2: chop feel (not started; requested by the user)

Start it after task 1 lands, because it touches the same files.

**Pitch matched to the tempo (varispeed).** The user said: "The sample chops never seem to change pitch... match the pitch to the BPM to slow it down or speed it up, then the natural cadence of the phrase matches better, making chops more accurate and interesting."
- Give each line one speed ratio, from its natural syllable or onset rate against the beat grid.
- Speed and pitch change together, like a turntable, within roughly ±2–3 semitones so words stay recognizable.
- Apply it in the pad bank builder or the chop render, off the audio thread.
- Re-measure the onsets on the resampled audio so the D126 tightness holds (median onset within ±2 ms of before, nothing worse than the baseline over 35 ms).
- Vary the ratio per line.

**Unpredictable but intentional patterns, with more reverses.** The user said: "There is always a reverse thing near this one spot after that it gets quiet. I want more changes... feel random, but intentional. Above all I shouldn't recognize patterns between different sample chops. A few more reverses throughout."
1. Measure first. Across many loops and lines, where do reverses, rests, rolls, stutters and the quiet moments land, by bar and step within the 16-bar arc (D126) and the chop beat (D127)?
2. Replace fixed placements with seeded draws from a pool of moves, with no fixed position. Never repeat the same move at the same position in consecutive loops. Keep memory across lines so one line's shape does not come back in the next.
3. Keep within-loop hook recurrence (D125) and the arc sections.
4. Add more reverses, preferably on salient words as pickups into downbeats.
5. Measure the result:
   - the per-position recurrence of each move across loops;
   - the similarity between consecutive loops' event grids;
   - the predictability of the next move.

   Gate these against the before numbers.

## How to work (environment notes)

- **Build:**
  - `xcodebuild -scheme Liminal -destination 'platform=macOS' build`
  - `xcodebuild -scheme Liminal -destination 'platform=visionOS Simulator,name=Apple Vision Pro' build`
- **Tests:** the narrower dialogue suites cover most of this work. The full `LiminalTests` run takes about 15 minutes.
  - `xcodebuild test -scheme Liminal -destination 'platform=macOS' -only-testing:LiminalTests/<Suite>`
- **App run on macOS (Debug):**
  - Flags: `-LiminalAutoPlay YES -archive.enabled YES -LiminalImageAPIFresh YES`. The last flag uses a throwaway picture pool, not the user's.
  - Logs: `/usr/bin/log stream --level info --predicate 'subsystem == "com.saygoodnight.Liminal"'`
  - Look for the `Lo-Fi dialogue hook` lines: `feel=`, `chopRepeat=`, `chopPieces=`, the line text and bars.
- **Captures:** `scripts/check-lofi.sh`, `scripts/mix-report.sh` and `scripts/mix-matrix.sh --strict` (see `docs/mix-verification.md`).
  - One capture at a time; each takes a lock.
  - Keep captures, WAVs and reports out of git.
- **Private files:** the drums (`Liminal/SlowBurnDrums/`, `SlowBurnBeatGrid.json`) are present locally and gitignored. Never commit them.
- **Device:** Vision Pro id `00008112-001430AC34D8A01E`. Only install when the user asks:
  - `xcodebuild ... -configuration Release -destination 'platform=visionOS,id=<id>' -allowProvisioningUpdates build`
  - then `xcrun devicectl device install app --device <id> <path>/Release-xros/Liminal.app`
- **Commits:**
  - plain sentence-case subjects;
  - keep docs in step with code: decision entries with dates and measurements, plus `architecture.md` and `experience.md`;
  - if new files are added, update the repository map in `CLAUDE.md` and `AGENTS.md`.
