# Current image pipeline (baseline, before feature/images changes)

## 1. Prompts
- Source: `VisualEngine.buildPrompt()` (Liminal/Visual/VisualEngine.swift ~L131-300), assigned as `imageQueue.promptBuilder`. Pure client-side templating, no LLM. Fallbacks: `"Abstract ambient visual"` (engine), `ImageQueue.defaultPrompt()`.
- Pools (uniform `randomElement()`): 50 scenes, 7 framings, 8 lighting, 5 realism (film/camera), 6 moods, 7 techniques, 13 wildcards (3 empty). About 50*7*8*5*6*7*13 combinations, but only `scene` changes subject matter; the rest are near-synonymous photographic modifiers.
- Template: `Photorealistic {framing} of {scene}. {Light}. {Mood}. {Technique}.[ {Wildcard}.] {Realism}. Natural, realistic colors. Hyper-detailed environment with realistic materials and physics. Looks like an actual photograph of an impossible place. Not illustration, not digital art, not CGI render. Real camera, real film, surreal subject.`
- Logged under `LMLog.prompt`. Scenes are ~80% "X where Y becomes Z" abstract metaphors (stacked moments in time, memories as sand, mirror showing other versions...). Many are not depictable as concrete objects.

## 2. Model call
- `GeminiClient` (final class, no actor): model `gemini-2.5-flash-image`, POST `v1beta/models/<model>:generateContent?key=<KEY>` (key in URL query), body = one text part, `generationConfig.responseModalities = ["TEXT","IMAGE"]`. NO `imageConfig`/aspectRatio, no seed/temperature, no system instruction, no negative prompt. Default output: 1024x1024 PNG (~1.5MB), square.
- Two near-duplicate methods: `generateImage` (PlatformImage, macOS) and `generateImageRaw` (PNG Data + CGImage via CGImageSource, visionOS). Takes first part with inlineData; text parts ignored. Errors: retried by `ImageQueue` only via 5s sleep after failure.

## 3. Pipeline (ImageQueue.generateAndUpscaleOne, continuous loop; VisualEngine timer calls `advance()` every `SettingsService.imageInterval`, default 30s)
- visionOS: Gemini raw -> `ImageUpscaler.upscale` (MetalFX on device, skipped in simulator, returns 1024 original) -> `AtomicImageBuffer.queuePending` (or `storeCurrent` if empty) -> saves RAW 1024 PNG bytes to cache.
- macOS: Gemini PlatformImage -> `ImageUpscaler.upscaleToCGImage` (CoreML RealESRGAN, input resized to 512x512, output 2048x2048, 30s timeout) -> `storeCurrent` if empty else `state.appendToBuffer` -> saves UPSCALED 2048 PNG.
- Note: the macOS RealESRGAN path squashes to 512 first, i.e. discards detail from 1024 (resolution loss for photorealism).
- Depth (visionOS only): `DepthMapGenerator` actor, DepthAnythingV2SmallF16 CoreML (fixed 518x392 input, grayscale 8-bit output), run in `ImmersiveDomeView` render loop when `AtomicImageBuffer.loadWithGeneration` generation changes (~31ms), stored via `storeDepth`, uploaded with `updateDepthTexture`. Depth is NOT cached to disk; recomputed per display. macOS: `DepthAnalyzer` (stats only).

## 4. Mapping to display
- Images are square. visionOS: `ImmersiveDomeView` curved panel (not a full sphere/equirect): `LowLevelDomeMesh` radius 2.0 m, horizontalArc 110, verticalArc 75, 48x36 segments, UV 0..1 across the whole panel. The effects shader renders into a 2048x2048 offscreen texture (`OffscreenEffectsRenderer.outputSize`), which is mapped onto the panel via stereo ShaderGraphMaterial. So a square image is stretched to ~1.47:1 (110x75 deg). Ken Burns scale 1.2 +/- 0.2 (`EffectsUniformsComputer.computeKenBurns`) crops further: viewer sees roughly the central ~80% of the image. Viewer only sees a 110x75 window in front of them; nothing behind.
- macOS: `EffectsMetalView` in an aspect-constrained window (ContentView "Window Aspect Ratio Constraint").
- Implication: generating a wide (16:9 or 3:2) image would match the 110x75 panel with less distortion; non-square needs renderer/uv care (another workstream owns renderers).

## 5. Caching
- `ImageCache` (not actor-isolated): `~/Library/Application Support/Liminal/RawImages` (visionOS reads/writes; 1024 PNG, UUID names) and `.../UpscaledImages` (macOS reads/writes; 2048 PNG). No metadata (no prompt/style sidecar), no eviction/size cap, no depth cache, no versioning. Newest-first by creation date.
- Memory: `AtomicImageBuffer` (current, next, depth, pendingQueue, generation counters), `ImageQueue.StateManager` actor (macOS: imageBuffer, cachedImages, displayed history), @Published counts, plus GPU textures in the renderers.
- Startup: visionOS loads all raw CGImages, upscales one random as the first image. macOS loads all upscaled PlatformImages into memory. With `cacheOnly` setting, visionOS `startCacheRecycler` loops random cached raws (array loaded once at start) through the upscaler into `queuePending`; macOS refills from cache.
- Settings in UserDefaults (`SettingsService`): imageInterval, cacheOnly.

## 6. Cache-clearing paths
- macOS `ContentView` (L265) and visionOS `ControlsView` (L267) buttons "Clear Image Cache": `ImageCache().clearAll()` + `clearAllRaw()` (delete *.png in each dir), each posts `.imageCacheCleared`.
- Observers: `ImageQueue.init` (clears AtomicImageBuffer incl. depth/pending, @Published, StateManager); ContentView/ControlsView refresh counts.
- Gaps: (a) only deletes `*.png` and only these two dirs (no other files/future dirs/depth); (b) NO confirmation; (c) visionOS cacheOnly recycler task holds its in-memory `rawImages` array and keeps re-queuing deleted images after a clear (not cancelled/reloaded); (d) running generation task may still enqueue an image mid-clear; (e) the renderer keeps its current/previous GPU textures and transition state until the next image; (f) `Reset All to Defaults` does not touch the cache; (g) cache count text in ControlsView computed once (`cache.count + cache.rawCount`), not live; (h) no clear for Gemini-produced images across app container on device other than via this button.

## 7. Why outputs look samey / illustrated
1. Only the subject varies; every prompt shares ~60 words of identical boilerplate ("natural realistic colors", "photograph of an impossible place", "tack sharp", "large format") which pins palette, lighting and style. "Natural, realistic colors" actively suppresses saturated/varied palettes.
2. Scene pool is abstract metaphor ("moments in time", "memories") that models render as glowy digital art / generic dreamscapes with galaxy/nebula/bioluminescent motifs; few concrete, recognizable objects.
3. Same bioluminescent/cosmic/fractal vocabulary repeated in scenes, wildcards, moods; negative phrasing ("Not illustration, not digital art, not CGI render") often primes the model toward those concepts.
4. Single style (photoreal landscape) - no style families (macro, product shot, analog film, architectural, studio object, etc.), no palette control, no composition control.
5. Model is gemini-2.5-flash-image at default 1024x1024 square with no aspect/size control; no seed diversity, no per-prompt palette.
6. Heavy downstream effects (hue shift, distortion, contrast) further normalize look; shader is another workstream.
7. macOS upscale path downsamples to 512 before RealESRGAN (soft/painterly).
